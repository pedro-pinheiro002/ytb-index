# ytb-index v1 — Specification

> **Status:** v1, draft → implementation-ready.
> **Source of truth for *why***: the closed wayfinder tickets linked from each section. This document restates only what's load-bearing; decisions live in their tickets.

---

## 1. Overview

`ytb-index` is a TypeScript service that turns one YouTube channel into a browseable web catalog. An operator runs `pnpm ingest <channel>` to fetch the channel's uploaded videos and top-level comments via the YouTube Data API v3, persist them to a local SQLite file, and serve a server-rendered web UI (`pnpm dev` / `pnpm start`) that surfaces **timestamped comments** — comments whose text mentions an offset like `5:32` or `1:23:45` — with each offset linking out to the YouTube player at that timestamp.

The intended user is a single operator running this against one channel they care about (their own, a creator they follow). One channel per run. One-shot fetch. No auth, no multi-tenant, no client-side JS framework — just HTML pages that link to YouTube.

---

## 2. Glossary

The canonical vocabulary lives in [`GLOSSARY.md`](../../GLOSSARY.md). The terms load-bearing for this spec:

- **Channel** — the single YouTube channel one ingest run fetches from.
- **Catalog** — the structured collection of videos + comments persisted by one ingest run. *Implicit, not a table:* all data for one channel shares `fetched_at`.
- **VideoRecord** — one video in the Catalog (`videos` table).
- **CommentRecord** — one top-level comment (`comments` table).
- **TimeAnchor** — a matched timestamp in a comment's text, parsed to `seconds: number` (`time_anchors` table).
- **TimestampedComment** — a `CommentRecord` whose text contains ≥ 1 `TimeAnchor`. Derived at read time as `comments.has_anchors = 1`.

When this spec says "top-level comment", it means `commentThreads.list`'s `snippet.topLevelComment` only; **replies are out of scope for v1** (§3).

---

## 3. Scope

### In v1

- Ingest **one channel per run** by handle (`@handle`), channel ID (`UC…`), or canonical URL.
- Fetch the channel's **uploaded videos** (uploads playlist) and **top-level comments** on every video.
- Detect timestamps in each comment's text and persist them as `TimeAnchor` rows.
- Persist to a **single SQLite file** (default `./catalog.sqlite`); overwrite-on-rerun (no diff, no incremental).
- Serve two SSR routes (`/`, `/v/:videoId`) from the same SQLite file; no client-side framework.
- Render every `TimeAnchor` as a link that opens YouTube in a new tab at the right offset.

### Out of v1

See the map's **[Out of scope](https://github.com/pedro-pinheiro002/ytb-index/issues/1)** for the canonical list: multi-channel catalogs · scheduled/periodic refresh · comment replies · YouTube embed/in-page seek · search/filter/sort on the catalog · per-user auth / OAuth · v2+ specs.

**TTL carve-out (ADR-0001)**: comment text older than 30 days is replaced at read time with a placeholder (§4, §6). The Developer Policies III.E.4.g 7-day deletion affordance is **exempt** in v1 — single-user personal app, no other users in the regulated sense.

## 4. Data Model

The SQLite schema is the authoritative artifact: [`docs/spec/v1/schema.sql`](./schema.sql) — design rationale in [#8](https://github.com/pedro-pinheiro002/ytb-index/issues/8).

### Tables at a glance

| Table | One row per | Key columns |
| --- | --- | --- |
| `channels` | YouTube channel | `id` (PK), `title`, `uploads_playlist_id`, `fetched_at` |
| `videos` | Uploaded video | `id` (PK), `channel_id` (FK), `title`, `published_at`, `thumbnail_url`, `duration_iso8601`, counts, `fetched_at` |
| `comments` | Top-level comment | `id` (PK), `video_id` (FK), `channel_id` (FK), `author`, `text`, `published_at`, `like_count`, `has_anchors`, `fetched_at` |
| `time_anchors` | Detected timestamp | `(comment_id, seconds)` (PK), `raw_text`, `char_position` |

### Read surface

Application code reads comments through the **`comments_active`** view, never the raw `comments` table. The view:

- Computes `expires_at = fetched_at + 30 days` at read time.
- Replaces `text` with `[Comment text expired — refresh to recover]` when `now > expires_at`.
- Keeps `time_anchors` rows for expired comments joinable (the anchor existed; the body is redacted).

Mechanism and reasoning: [ADR-0001 — TTL policy](../adr/0001-ttl-policy.md).

### Indices

- `idx_videos_channel_id`, `idx_videos_channel_published` (composite, serves the catalog-page sort).
- `idx_comments_video_id`, `idx_comments_channel_id`.
- `time_anchors` PK `(comment_id, seconds)` covers all v1 read paths.

### Glossary → table mapping (pinned in #8)

| Glossary term | Realization |
| --- | --- |
| Channel | `channels` row |
| VideoRecord | `videos` row |
| CommentRecord | `comments` row |
| TimeAnchor | `time_anchors` row |
| Catalog | implicit (one channel = one catalog, shared `fetched_at`) |
| TimestampedComment | `comments.has_anchors = 1`, evaluated at query time |

### TTL column requirement (ADR-0001)

Every public-API-data table (`channels`, `videos`, `comments`) carries `fetched_at TEXT NOT NULL` (ISO-8601 UTC). `expires_at` is computed at read time, not stored. `time_anchors` has no `fetched_at` — it inherits freshness from the parent comment.

## 5. Ingest Pipeline

Run via `pnpm ingest <channel>`. Full step list + error matrix in [#2](https://github.com/pedro-pinheiro002/ytb-index/issues/2). TimeAnchor detection algorithm in [#7](https://github.com/pedro-pinheiro002/ytb-index/issues/7).

### Ordered steps

1. `dotenv.config()`; load `YOUTUBE_API_KEY`. Validate via `src/yt/api-key.ts` (§8).
2. Parse CLI args: `<channel>` required, `--verbose` optional.
3. Normalize input → `{handle, id}`; reject anything else with a usage error.
4. Resolve channel via `channels.list?part=snippet,contentDetails` (1 unit).
5. Upsert `channels` row; `fetched_at = now()`.
6. Page `playlistItems.list?part=snippet&playlistId=<uploads>&maxResults=50` (1 unit/page) → collect video IDs.
7. Enrich in batches of 50 via `videos.list?part=snippet,contentDetails,statistics&id=<50 IDs>` (1 unit/batch). Upsert `videos`.
8. Per video, page `commentThreads.list?part=snippet&videoId=<id>&maxResults=100` (1 unit/page). Capture `snippet.topLevelComment`. **Skip `replies.comments[]` (top-level only).**
9. Detect `TimeAnchor`s per [#7] in each comment; insert into `time_anchors`; set `comments.has_anchors = 0|1`.
10. Upsert `comments`; `fetched_at = now()`.
11. Increment quota counter; warn at 8 000 units, abort at 9 500.
12. Print summary: `channels=1 videos=N comments=N anchors=N duration=Xs quota=N`.

The whole run commits in one transaction (ADR-0001 overwrite behavior).

### Input parser

```
input = "<channel>"
if input starts with "https://youtube.com/channel/"  → id = tail
elif input starts with "https://youtube.com/@"        → handle = "@" + tail
elif input starts with "@" or ^[A-Za-z0-9_-]+$        → handle = input (with or without @)
elif input matches /^UC[A-Za-z0-9_-]{22}$/            → id = input
else → usage error
```

### Error-handling matrix

| Stage | Error | Behavior | Exit |
| --- | --- | --- | --- |
| Channel resolve | `404 channelNotFound` / unknown id | Fail fast | `1` |
| Channel resolve | Network / 5xx / 429 | Retry 1s → 2s → 4s (3×), then fail | `1` |
| Any stage | `403 quotaExceeded` | Fail fast; print `[ERROR] quota exhausted, resets at midnight Pacific Time` | `2` |
| Any stage | `400 invalidPageToken` | Fail fast (programming error) | `1` |
| Per-video comments | `403 commentsDisabled` | Skip video; log; continue | `0` |
| Per-video comments | `404 videoNotFound` | Skip; log; continue | `0` |
| Any stage | `429 rateLimitExceeded` / 5xx / `ETIMEDOUT` / `ECONNRESET` | Retry 1s → 2s → 4s (3×), then fail | `1` |
| Any stage | Unknown error | Fail fast; print full Google API error envelope | `1` |

**Philosophy**: skip-and-continue for *per-video* errors (a handful of dead videos don't poison a channel run); fail-fast for *channel-level* errors and quota exhaustion (non-recoverable in the current run).

### Logging

- **Default** — milestone lines per stage transition on stdout (see full list in #2).
- **`--verbose`** — additionally one line per API call and per-video timings.
- **Errors** — always print the full Google API error envelope.
- **Exit codes** — `0` success (per-video skips still success), `1` user/config/network error, `2` quota exhausted.

### TimeAnchor detection (#7)

Run at step 9 on every comment text. Row shape: `(comment_id, seconds, raw_text, char_position)`; PK `(comment_id, seconds)` (dedup keeps earliest `char_position`).

- `h:mm:ss` — permissive; matched anywhere.
- `mm:ss` — sentinel-anchored; one of `at` / `@` / `jump to` / `skip to` / `go to` / `fast forward to` / `the … mark` / `… onwards` / `… forward` / `is the …` / `is where` / `is when` / `from` / `by` / `… to …`.
- Bare `5:32` (no sentinel) is **not** matched in v1.
- All top-level comments persist regardless of anchor presence (`has_anchors = 0` if none).

Algorithm regexes and parsing pseudocode: see #7 resolution.

### API endpoints used (research, [#9](https://github.com/pedro-pinheiro002/ytb-index/issues/9))

| Call | Endpoint | Cost |
| --- | --- | --- |
| Channel resolve | `channels.list?part=snippet,contentDetails` | 1 unit |
| Uploads playlist | `playlistItems.list?part=snippet&playlistId=<uploads>&maxResults=50` | 1 unit / page |
| Video metadata | `videos.list?part=snippet,contentDetails,statistics&id=<≤50>` | 1 unit / batch |
| Comments | `commentThreads.list?part=snippet&videoId=<id>&maxResults=100` | 1 unit / page |

API key is sufficient (read-only public data). No OAuth. Default quota 10 000 units/day, resets midnight Pacific. `quotaExceeded` = HTTP 403.

## 6. UI

Two SSR routes, un-namespaced. Full wireframes in [#5](https://github.com/pedro-pinheiro002/ytb-index/issues/5).

### Routes

- `GET /` — catalog index page.
- `GET /v/:videoId` — video detail page.

### Catalog index (`/`)

Each row:

- Thumbnail (left, ~120 px wide, `alt="<video title>"`; fallback `alt="Video thumbnail"`).
- Title (link to `/v/:videoId`).
- Relative published date.
- One-line summary: `N comments / K timestamped`.

Plus a **"Last refreshed: YYYY-MM-DD"** line near the channel header (ADR-0001).

### Video detail (`/v/:videoId`)

Header:

- `<h1>` title.
- Medium thumbnail.
- Relative published date.
- Primary button: `<a target="_blank" rel="noopener noreferrer" href="https://www.youtube.com/watch?v={videoId}">Watch on YouTube</a>`.

No description. No channel-name link.

Body — all top-level comments, newest first.

### TimestampedComment visual treatment

- 3px solid left-border accent in a brand color.
- Footer line: `Timestamps: 1:23 · 5:32 · 12:04` (middle-dot separator; each entry is a click-jump link).
- The comment body itself is rendered as-is; `TimeAnchor`s inside the text are themselves clickable. The footer is a summary, not a re-render of the in-text anchors.

### Click-jump URL

```
https://www.youtube.com/watch?v={videoId}&t={seconds}s
```

Every anchor link (in-text and footer) carries `target="_blank" rel="noopener noreferrer"`. No `&feature=` (YouTube-internal cross-tracking). `{seconds}` is `time_anchors.seconds` (INTEGER, from #7's parsing).

### Empty states

| State | Render |
| --- | --- |
| Channel with no videos | `No videos ingested. Run pnpm ingest <channel> to populate.` |
| Channel with videos, zero timestamped | Videos render with `0 timestamped` summary |
| Video with no comments | `No comments on this video.` |
| Video with comments, zero timestamped | Comments render without the `Timestamps:` footer |
| Comment past 30-day TTL | `text` replaced with `[Comment text expired — refresh to recover]`; anchor links stay |

### Pagination

None in v1. All videos on one page. `idx_videos_channel_published` keeps the catalog query cheap; add pagination in v2 if a real channel breaks the page.

## 8. API Key Management

Locked in [#11](https://github.com/pedro-pinheiro002/ytb-index/issues/11). The architectural fact driving this section: the Hono server reads SQLite only — no YouTube API calls in the request path — so the API key is a **CLI concern**, not a server concern.

### `.env`

```
YOUTUBE_API_KEY=AIza...   # ~39 chars total, AIza + 35 base64-ish
```

Loaded by `dotenv.config()` once at process start in both `pnpm ingest` and `pnpm dev` / `pnpm start`.

### Server (`pnpm dev` / `pnpm start`)

- **Does not require** `YOUTUBE_API_KEY`. Boots without it; serves the catalog normally.
- Optional boot-time warning if missing, to flag that `pnpm ingest` will be broken.

### CLI (`pnpm ingest <channel>`)

Validates at **step 1** of the pipeline (§5), before CLI arg parsing, before DB connect, before any API call. Cheapest possible fail — a bad key never opens the SQLite file, never burns quota, never looks up argv.

Two synchronous local checks (no API probe; probing wastes quota and defeats fail-fast):

1. **Presence** — non-empty after `.trim()`. Reject `undefined`, `""`, `"   "`.
2. **Shape** — match `^AIza[A-Za-z0-9_-]{30,50}$`.

### Validation helper (`src/yt/api-key.ts`)

```ts
export type ApiKeyValidation =
  | { ok: true }
  | { ok: false; reason: 'missing' | 'malformed' };

export function validateApiKey(key: string | undefined): ApiKeyValidation {
  if (key === undefined || key.trim() === '') return { ok: false, reason: 'missing' };
  if (!/^AIza[A-Za-z0-9_-]{30,50}$/.test(key)) return { ok: false, reason: 'malformed' };
  return { ok: true };
}
```

Lives in `src/yt/` (it knows YouTube key shape); `shared/` is for types only. Pure function, trivially unit-testable.

### Failure messages (both exit `1`)

| Failure | stderr |
| --- | --- |
| Unset / empty | `Error: YOUTUBE_API_KEY is not set. Add it to your .env file.` |
| Wrong format | `Error: YOUTUBE_API_KEY has unexpected format (expected "AIza" + ~39 chars). Check the value in .env.` |

### Runtime API rejection

After step 1, every API call is governed by §5's error matrix. **No new exit codes:**

- `400`/`401`, `403 keyInvalid`, `403 permissionDenied` → exit `1`, print full Google API error envelope.
- `403 quotaExceeded` → exit `2`.

### Failure-mode summary

| Entrypoint | Key state | Behavior |
| --- | --- | --- |
| `pnpm ingest` | Unset / empty | stderr message; exit `1` |
| `pnpm ingest` | Wrong format | stderr message; exit `1` |
| `pnpm ingest` | Valid shape, API rejects 400/401 | step 4 fail; exit `1` |
| `pnpm ingest` | Valid shape, API 403 keyInvalid | step 4 fail; exit `1` |
| `pnpm ingest` | Valid shape, API 403 quotaExceeded | step 4+ fail; exit `2` |
| `pnpm dev` / `pnpm start` | Unset | boot OK; optional warning that ingest is broken |
| `pnpm dev` / `pnpm start` | Wrong format | boot OK; optional warning |
| `pnpm dev` / `pnpm start` | Valid shape, rejected | not consumed — server doesn't call API |

## 9. Open Questions

The map's **[Not yet specified](https://github.com/pedro-pinheiro002/ytb-index/issues/1)** holds the fog that hasn't graduated. Items that still apply at spec time:

- **Spec formatting conventions** — exact heading depth, link style, length budget. The current 9-section layout is the convention this v1 settles on; revisit if a v1.1 spec is ever written.
- **Uncertain API claims** (from [#9](https://github.com/pedro-pinheiro002/ytb-index/issues/9); not blockers, but the spec should note as assumptions):
  - "Non-Authorized Data" is not formally defined in YouTube Developer Policies; the 30-day cap's applicability to public comments is an inference. v1 treats it as binding per ADR-0001.
  - Uploads-playlist ordering (newest-first) is observed but undocumented in primary sources.
  - `searchTerms` matching semantics (fields searched, substring vs token) are unspecified.
  - Per-minute rate limits for `youtube.googleapis.com` are not published.
  - `order=time` direction for `commentThreads.list` is unspecified.

If any of these assumptions turn out to be wrong at runtime, file a follow-up ticket and patch the spec — but don't block v1 on resolving them.
